# 九十秒导览

*这是什么，按读者遇见它的顺序讲。*

## 问题，用一句话说

你走进一间自习室，坐下，打开笔记本，插上电——什么也没有发生。插座是坏的，而桌子、门和学校自己的系统
都没有在你坐下来之前告诉你。

## 单位是插座，不是房间

订位系统数的是房间。报修系统数的是故障。两者都没有回答你真正关心的那个问题，也就是你面前这张桌子。
一个房间可以是「有空位」的，而里面唯一那张空桌却是没用的，所以 Sure Socket 给每个插座自己的身份：

```
CPD-LG01-0001     楼栋 · 房间 · 四位序号
```

这个编号分配一次，永不复用。学生把它念出来，维修人员在队列里读到同一个字符串，数据库也拒绝两个插座
共用同一个编号——这个编号是所有人争论的对象，所以它在任何地方都必须是同一个东西。

![房间里的桌子，每个插座按它最后一次已知的状态上色](screens/desktop/02-room-and-plan.jpg)

## 产品围绕的三个时刻

1. **找。** 选一栋楼，选一个房间，看到每个插座按最后一次已知的状态上色，旁边是上次核查的日期。
   房间平面图把颜色放在它们所属的桌子上，所以你看的是桌子，而不是一张列表。
2. **报。** 四个选择——楼栋、房间、插座编号、哪里坏了——从一个已打开的房间出发是三次点击。
   插座当场变色，所以你能看到自己的上报落地。
3. **修。** 维修人员得到一条队列，按最旧的核查排在最前，每行还带着它背后的账号数。关闭一次修复会
   盖上时间戳，房间显示新的状态，下一名学生读到它。

![房间平面图：每个插座一个颜色块，标着它的编号](screens/mobile/05-phone-room.jpg)

## 评审者第一眼看到的东西

房间选择页：四栋楼，楼下的房间，以及每个房间里正常、松动、损坏和未核查插座的计数。一次点击，一个陌生人
就正看着某个特定的房间、某个特定的楼层、某个被标成红色的特定插座——没有登录墙，不用搭建，不需要解释。
