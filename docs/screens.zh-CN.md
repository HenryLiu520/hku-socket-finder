# 界面截图

这个版本里的每一个界面，按学生遇到它们的顺序排列，最后加上两个手机布局。
所有图片都由 `scripts/capture_screens.py` 从运行中的应用截取，展示的是真实产品而不是效果图。

## 找插座

第一屏是一个三步选择器——先选楼，再选房间——每张房间卡片上都写着里面有多少个插座有问题，
不用走到门口就知道。

![找插座](screens/desktop/01-find-a-socket.jpg)

## 房间与平面图

打开一个房间：平面图按座位画出，每个插座是一枚小标签，只显示贴纸上编号的后四位，
下面用表格列出同一批插座。

![房间与平面图](screens/desktop/02-room-and-plan.jpg)

## 上报故障

上报表单依次询问楼、房间、插座和状态，上一步没有填完就不会往下走。

![上报故障](screens/desktop/03-report-a-fault.jpg)

## 维修队列

同一批记录在维修人员这一侧：坏掉的插座按时间从旧到新排列，附上同意的学生人数、已经坏了多久，
每行还有一个按钮把它关掉。

![维修队列](screens/desktop/04-repair-queue.jpg)

## 手机上的房间页

同样一个房间在手机宽度下的样子——平面图、颜色说明和插座表格竖排成一列，
你从桌上读到的编号始终留在屏幕上。

![手机上的房间页](screens/mobile/05-phone-room.jpg)

## 手机上的上报页

手机上的上报表单：每行一个字段，状态按钮折成两行，
询问的仍然是桌面版那四步。

![手机上的上报页](screens/mobile/06-phone-report.jpg)

## 运行演示数据

上面的图片都是在演示数据集上截的，`scripts/demo-reset.sql` 能把数据库恢复成完全一样的状态：
它先清空所有上报和维修记录，把所有插座重置为 `UNKNOWN`，再为一组挑好的插座写入两条互相印证的上报，
让颜色、时间和上报人数都对得上。种子数据导入之后，对着演示数据库执行：

```bash
psql -h 127.0.0.1 -p 5433 -d socketfinder -v ON_ERROR_STOP=1 -f scripts/demo-reset.sql
```

重复执行是安全的——它先删后插，并且故意留一个插座没有检查记录，
好让演示时可以现场上报、看着状态翻转。

最后两张是手机版界面，就在同一个应用的 `/m` 下：四个标签页（查找、房间、上报、我的），固定顶栏与底部标签栏，按 390×844 的屏幕设计。
