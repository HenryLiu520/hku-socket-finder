## 证据规则

一份上报不是一票，而是一个权重。每个账号都带着 0.5 到 1.5 之间的权重，权重由它过去的上报被结算的情况算出来。要判断一个插座的状态，接口会读取最近 72 小时内在这个插座上提交的每一份上报，只保留每个账号最新的一份，按它们声称的状态分组，再把每组里最重的三个权重相加。某一组的总和达到 1.6 **并且** 至少是第二名总和的 1.5 倍时，这个状态才成立。两项都不满足，插座就保持原来的状态；那份上报仍然会被保存，也仍然计入下一个窗口。

管事的其实是算术。单个权重的上限是 1.5，低于 1.6，所以一个账号无论记录多好，都不可能独自翻转一个插座。两个权重为中性 1.0 的账号相加是 2.0——超过阈值，而且是 2.0 比 0 的领先。一个有争议的插座，比如一边声称 2.0、另一边 1.5，就过不了 1.5 倍这一关，会保持原来的状态，直到有人再说一句。

什么都没改变的上报，回答的是还差多远：“上报已保存。改变状态需要 1.6 份证据，目前 1.0 份”，房间视图在点一下之后显示的就是这句话。

## 一表说清规则

| 规则 | 这一版里的数值 | 它挡住了什么 |
|---|---|---|
| 成立一个状态所需的证据 | 1.6，由同一状态背后最重的几个权重相加 | 一份上报就挪动一个插座 |
| 对第二名的领先 | 第二重那组总和的 1.5 倍 | 两种说法之间靠掷硬币决定 |
| 证据窗口 | 72 小时，且只取每个账号在窗口内最新的一份上报 | 一个意见活得比故障还久 |
| 计入的账号 | 最重的三个，且没有权重高于 1.5 | 一个人独自翻转一个插座 |
| 一份上报的权重 | 0.5 + 分数，即 0.5 到 1.5；新账号的权重是 1.0 | 喊得最响的人压过说得最准的人 |
| 账号的分数 | (confirmed + 2.5) / (settled + 5) | 一份走运的上报定义一个账号 |
| 上报限制 | 每个插座每 24 小时一份，每个账号每天十份，两者都是 HTTP 429 | 一个人一小时内扫完一层楼 |

## 分数怎么动

分数不是计数，而是带先验的错误率：`(confirmed + 2.5) / (confirmed + refuted + 5)`，背后的先验是 Beta(2.5, 2.5)。新账号停在 0.5，权重 1.0；结算过的上报全对的账号，权重趋近 1.5；总是报错的账号，权重慢慢滑向 0.5。`GET /api/auth/me` 返回分数、权重和两个计数器。

只有一个事件会动这些计数器：维修。维护人员把一个插座标为已修，接口就写一行维修记录，带上维修人员账号、时间和一个可选的备注，把插座设为已修，盖上核查时间，然后结算 72 小时窗口里的每一份上报——说中了插座当时状态的上报记为 confirmed，其余的记为 refuted。别的事情都碰不到这些计数器：上报不碰，状态翻转不碰，登录也不碰。对一个不是松动、没电或损坏的插座做维修，什么都结算不了，所以把一个正常插座标成已修，拿不到任何信用。

## 两条频率限制

两条都是按账号算的，都返回 HTTP 429：

- **每个插座每 24 小时一份上报。** 再试一次返回 `TOO_SOON`，“You already reported this socket today”。
- **每天十份上报。** 从当地零点起算；第十一份返回 `DAILY_CAP`，“That is 10 reports today, come back tomorrow”。

其他的拒绝都小且精确：不认识的插座是 404，works / loose / no power 之外的状态是 400 `BAD_STATE`，缺少 token 是 401，角色不对是 403。

## 什么会被标成过期

超过 30 天的核查就算过期。它是在读一个插座时算出来的，由一个只接收核查时间和时钟的纯函数算出来，所以不会有哪个后台任务和它描述的那一行走偏。过期的插座保留自己的状态：它在房间视图里被标成“旧”，并被“旧”这个筛选收进去，而一个没人查过的插座显示的是“从未检查”，而不是一个天数。

## 谁可以关掉一个故障

维护人员，而且只有维护人员。这道检查放在写操作所在的控制器里，不放在界面里，所以不管按钮怎么摆，学生去调维修接口拿到的都是 403。证据翻转一个状态时，盖上核查时间的是服务器，不是浏览器。

## 已知限制

- **token 存在内存里。** 它们待在接口进程里的一个 map 中，八小时后失效；重启会让所有人退出登录，第二个实例也不会共享它们。
- **登录接口没有频率限制。** 没有任何东西能让猜密码的人慢下来，这之所以还能忍，只因为这些是演示账号，密码是公开的。
- **账号是预置的，不是验证过的。** 应用在第一次启动时创建三个；没有任何东西能证明一个账号属于港大学生。
- **房间是样数据。** 楼、座位和插座都是手写的迁移行，只有四栋楼，不是整个校园。
- **证据到三个账号就停。** 第四个学生同意，对总和没有任何贡献，所以一大群人不比三个说得准的账号更有说服力。
- **诚实是有代价的，不是被证明的。** 接口看不到一份上报是不是真的；它只能让一份错误的上报在下次维修时付出权重的代价。
