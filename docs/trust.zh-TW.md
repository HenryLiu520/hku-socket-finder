## 證據規則

一份上報不是一張選票，而是一個權重。每個帳號都帶著 0.5 到 1.5 之間的權重，由它過去的上報被結算的結果算出來。要判定一個插座的狀態，API 會讀取過去 72 小時內針對這個插座的所有上報，每個帳號只保留最近的一筆，把這些上報按它們宣稱的狀態分組，再把每組裡最重的三個權重相加。當某一組的總和達到 1.6 **而且** 至少是第二名總和的 1.5 倍時，那個狀態才成立。兩項測試只要有一項沒過，插座就維持原本的狀態；上報仍然會被存下來，也仍然算進下一個窗口。

治理的是算術本身。任何單一權重的上限是 1.5，低於 1.6，所以一個帳號無論紀錄多好，都不可能單獨翻轉一個插座。兩個處於中性權重 1.0 的帳號相加是 2.0——越過門檻，而且是 2.0 對 0 的領先。一個有爭議的插座，比如一邊宣稱 2.0、另一邊 1.5，就過不了 1.5 倍那一項測試，會一直維持原本的狀態，直到有另一個人開口。

一筆什麼都沒改變的上報，會用走過的距離來回答：「上報已儲存。改變狀態需要 1.6 份證據，目前累積到 1.0 份」，也就是房間頁在按一下之後顯示的那句話。

## 規則一覽表

| 規則 | 這個版本裡的數值 | 它擋掉了什麼 |
|---|---|---|
| 取得一個狀態所需的證據 | 1.6，由同一個狀態背後最重的幾個權重相加 | 單一筆上報就把插座移走 |
| 對第二名的領先 | 第二重總和的 1.5 倍 | 兩種宣稱之間的五五波 |
| 證據窗口 | 72 小時，而且只取每個帳號在這段時間內最新的一筆 | 一個意見活得比故障還久 |
| 計入的帳號 | 最重的三個，且沒有任何權重高於 1.5 | 一個人單獨翻轉一個插座 |
| 一筆上報的權重 | 0.5 + 分數，也就是 0.5 到 1.5；新帳號是 1.0 | 聲音最大的人壓過講得最準的人 |
| 一個帳號的分數 | (confirmed + 2.5) / (settled + 5) | 一筆僥倖的上報就定義了一個帳號 |
| 上報限制 | 每個插座每 24 小時一筆，每個帳號每天十筆，兩者都回 HTTP 429 | 一個人在一小時內掃完整層樓 |

## 分數如何移動

分數是一個帶先驗的錯誤率，不是一個計數：`(confirmed + 2.5) / (confirmed + refuted + 5)`，它背後的先驗是 Beta(2.5, 2.5)。新帳號停在 0.5，權重是 1.0；被結算的上報全部判對的帳號，權重會趨近 1.5；總是判錯的則往 0.5 漂。`GET /api/auth/me` 會回傳分數、權重和兩個計數。

被結算過的上報同時退出證據池：維修判過的上報不再投票，也不會被結算第二次。只有一件事會改動這些計數：一次維修。維護人員把插座標為已修復，API 就寫下一筆 repair 資料列，含工作人員帳號、時間和一段可選備註，把插座設為已修復、蓋上核查時間，然後結算 72 小時窗口內的每一筆上報——指出的狀態正是插座當下狀態的算 confirmed，其餘算 refuted。其他任何事都碰不到這些計數：上報不算、狀態翻轉不算、登入也不算。對一個狀態不是鬆脫、無電或損壞的插座做維修，什麼都不會結算，所以把一個正常插座標成已修復並不會換到任何信用。

## 兩道速率限制

兩道都是按帳號計，兩道都回 HTTP 429：

- **每個插座每 24 小時一筆上報。** 第二次嘗試會回 `TOO_SOON`，「你今天已經上報過這個插座」。
- **每天十筆上報。** 從當地午夜開始算；第十一筆回 `DAILY_CAP`，「今天已經 10 筆上報，明天再來」。

其他的拒絕都簡短而精確：不存在的插座是 404，狀態不在 works / loose / no power 之內是 400 `BAD_STATE`，少了權杖是 401，角色不對是 403。

## 什麼會被標為過時

超過 30 天的核查就是過時。它是在讀取插座時算出來的，由一個只拿到核查時間和當下時鐘的純函式負責，所以不會有背景工作跟它所描述的那一列走散。過時的插座保留它的狀態：在房間頁上被標上「old」標籤，並被「過時」篩選收集；而從沒有人核查過的插座，顯示的是「從未核查」，而不是一個年齡。

## 誰可以結案

維護人員，而且只有維護人員。這項檢查放在控制器裡的寫入路徑上，不在介面裡，所以學生就算去呼叫維修端點也只會拿到 403，按鈕怎麼排都一樣。當證據翻轉一個狀態時，蓋上核查時間的是伺服器，不是瀏覽器。

## 已知限制

- **權杖只存在記憶體裡。** 它們放在 API 行程內的一個 map 中，八小時後過期；重啟就把所有人登出，而第二個執行個體也不會共享它們。
- **登入端點沒有速率限制。** 沒有東西能拖慢猜密碼的人，這之所以還算可以接受，只因為這些帳號是密碼公開的示範帳號。
- **帳號是預先建立的，不是驗證過的。** 應用程式在第一次啟動時建立三個；沒有東西能證明某個帳號屬於一位港大學生。
- **房間是樣本資料。** 樓宇、座位和插座都是手寫的遷移資料列，只有四棟樓，不是整個校園。
- **證據只算到三個帳號。** 第四個學生同意不會為總和加上任何東西，所以一大群人不比三個準確的帳號更有說服力。
- **誠實是有代價的，不是被證明的。** API 看不到一筆上報是否為真；它只能讓一筆錯誤的上報在下一次維修時損失權重。
