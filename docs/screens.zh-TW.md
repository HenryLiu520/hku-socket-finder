# 介面截圖

這個版本裡的每一個介面，按學生遇到它們的順序排列，最後加上兩個手機版面。
所有圖片都由 `scripts/capture_screens.py` 從執行中的應用程式截取，呈現的是真實產品而不是示意圖。

## 找插座

第一屏是一個三步選擇器——先選樓，再選房間——每張房間卡片上都寫著裡面有多少個插座有問題，
不用走到門口就知道。

![找插座](screens/desktop/01-find-a-socket.jpg)

## 房間與平面圖

打開一個房間：平面圖按座位畫出，每個插座是一枚小標籤，只顯示貼紙上編號的後四碼，
下面用表格列出同一批插座。

![房間與平面圖](screens/desktop/02-room-and-plan.jpg)

## 上報故障

上報表單依次詢問樓、房間、插座和狀態，上一步沒有填完就不會往下走。

![上報故障](screens/desktop/03-report-a-fault.jpg)

## 維修隊列

同一批記錄在維修人員這一側：壞掉的插座按時間由舊到新排列，附上同意的學生人數、已經壞了多久，
每行還有一個按鈕把它關掉。

![維修隊列](screens/desktop/04-repair-queue.jpg)

## 手機上的房間頁

同樣一個房間在手機寬度下的樣子——平面圖、顏色說明和插座表格豎排成一欄，
你從桌上讀到的編號始終留在螢幕上。

![手機上的房間頁](screens/mobile/05-phone-room.jpg)

## 手機上的上報頁

手機上的上報表單：每行一個欄位，狀態按鈕折成兩行，
詢問的仍然是桌面版那四步。

![手機上的上報頁](screens/mobile/06-phone-report.jpg)

## 執行示範資料

上面的圖片都是在示範資料集上截的，`scripts/demo-reset.sql` 能把資料庫還原成完全一樣的狀態：
它先清空所有上報和維修記錄，把所有插座重設為 `UNKNOWN`，再為一組挑好的插座寫入兩筆互相印證的上報，
讓顏色、時間和上報人數都對得上。種子資料匯入之後，對著示範資料庫執行：

```bash
psql -h 127.0.0.1 -p 5433 -d socketfinder -v ON_ERROR_STOP=1 -f scripts/demo-reset.sql
```

重複執行是安全的——它先刪後插，並且故意留一個插座沒有檢查記錄，
好讓示範時可以現場上報、看著狀態翻轉。

最後兩張是手機版介面，就在同一個應用的 `/m` 下：四個分頁（查找、房間、上報、我的），固定頂欄與底部分頁列，按 390×844 的螢幕設計。
