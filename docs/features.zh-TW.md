# 功能

*這個正在跑的版本裡的每一項能力、擁有它的角色，以及證明它的畫面。*

兩個角色，一個版本。學生找到一個房間、讀每個插座的狀態、上報一個故障；物業處處理隊列並結案維修。下面沒有一列是假的：每一列都是 API 今天就會回答的請求。

| 能力 | 角色 | 在哪裡看得到 |
|---|---|---|
| 先選樓宇，再逐層選房間 | 學生 | 找插座（`/`）—— 樓宇分頁，一層一個區塊 |
| 按房號或名稱搜尋房間 | 學生 | 找插座頁的搜尋欄位 |
| 房間排序讓有故障的排在最前面 | 學生 | 找插座 —— 每張房間卡片上的狀態標籤 |
| 在平面圖上看房間裡的每個插座，按狀態上色 | 學生 | 房間頁 —— 由該房間的座位和插座畫出來的 SVG 平面圖 |
| 讀出上次核查有多舊 | 學生 | 房間頁 ——「上次變更」欄，帶「old」標籤 |
| 把清單篩成全部 / 故障 / 過時 | 學生 | 房間頁 —— 表格上方的篩選 |
| 在房間頁裡按三下上報正常、鬆脫或無電 | 學生 | 在平面圖上按一個插座，再選故障類型，或 `POST /api/sockets/{id}/report` |
| 用輸入插座編號的方式上報，不用按 | 學生 | 上報故障（`/report`），第 3 步 |
| 看見一筆宣稱離 1.6 門檻還有多遠 | 學生 | 送出上報後回傳的訊息 |
| 登入並按角色被導向 | 兩者 | 登入（`/login`）；`/maintenance` 會把學生送回首頁 |
| 切換介面語言，English / 简体中文 / 繁體中文 | 兩者 | 頁首的三個語言按鈕 |
| 不用輸入帳密就能試示範帳號 | 兩者 | 登入頁的捷徑標籤，來自 `GET /api/auth/demo-accounts` |
| 處理維修隊列，先做核查最舊的，每一列都帶著背後有幾個帳號 | 維護人員 | 維修隊列（`/maintenance`） |
| 結案一個故障，可附備註 | 維護人員 | 隊列上的「標為已修復」；`POST /api/sockets/{id}/repair` |
| 查看自己的紀錄：信譽分、權重、已證實與被否定條數，以及正在努力的徽章 | 學生 | 我的紀錄（`/me`，手機版第四個分頁） |

## 刻意不做的事

- **照片證據。** 規則必須讀得懂照片才能改變狀態；證據規則只算帳號。
- **通知。** 沒有電郵也沒有推送，因為這個循環靠的是下一次造訪，而不是一個警示。
- **自行註冊。** 帳號是預先建立的，這樣每一筆上報都已經有一個權重會動的主人。
- **留言和討論串。** 下一位讀者在桌前需要的是狀態、數量和日期。
- **徽章。** 按被證實的上報計數，在 `/me` 與手機版第四個分頁顯示：1 / 5 / 10 / 25 條。**折抵券**沒有任何程式發放，只有徽章階梯是實作的。
- **離線模式和編輯。** 插座的編號由遷移寫一次，介面裡永遠不改。

## 需要種子資料的幾列

有三列靠的是種子資料而不是規則。隊列會有東西，只因為遷移 V6 把 `MW-T1-0003` 標成鬆脫、把 `CPD-LG01-0007` 標成無電，而 V7 在 Study room 4 留了兩個死掉的插座。過時標籤在第一次載入就出現，只因為 `KK-101-0004` 被蓋成 45 天前。上報和維修的資料列，在有人登入之前根本無從示範，而兩個示範學生都從權重 1.0 起步，背後沒有任何被結算的上報。
