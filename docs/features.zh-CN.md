# 功能

*这一版里每一个能力、握着它的角色，以及能证明它的界面。*

两个角色，一个版本。学生找到房间、读出每个插座的状态、报一个故障；物业办公室处理队列、关掉维修单。下面没有一条是模型稿：每一行都是接口今天真的会回答的请求。

| 能力 | 角色 | 在哪里看到 |
|---|---|---|
| 先选楼，再选房间，一层一层往下 | 学生 | 找插座（`/`）——楼的分页，每层一块 |
| 用房号或房间名搜索 | 学生 | 找插座页上的搜索框 |
| 房间排序把有故障的排在最前面 | 学生 | 找插座——每张房间卡片上的状态标签 |
| 在平面图上看到房间里每一个插座，按状态上色 | 学生 | 房间视图——一张按房间的座位和插座画出来的 SVG 平面图 |
| 读出上一次核查有多旧 | 学生 | 房间视图——“最后变化”这一列，带“旧”标签 |
| 把列表筛成全部 / 故障 / 旧 | 学生 | 房间视图——表格上方的筛选 |
| 点一下就能上报正常、松动或没电 | 学生 | 在平面图上点一个插座，或 `POST /api/sockets/{id}/report` |
| 不打点，改成输入插座编号上报 | 学生 | 上报故障（`/report`），第 3 步 |
| 看到一份说法离 1.6 阈值还差多远 | 学生 | 发出上报后返回的那句话 |
| 登录，并按角色被送到该去的地方 | 两者 | 登录（`/login`）；`/maintenance` 会把学生送回首页 |
| 切换界面语言，English / 简体中文 / 繁體中文 | 两者 | 页头三个语言按钮 |
| 不用输账号密码就能试演示账号 | 两者 | 登录页的账号小条，来自 `GET /api/auth/demo-accounts` |
| 处理维修队列，核查最旧的排前面，每行带着背后的账号数 | 维护人员 | 维修队列（`/maintenance`） |
| 关掉一个故障，可以带一条备注 | 维护人员 | 队列上的“标记已修”；`POST /api/sockets/{id}/repair` |

## 故意不做的

- **照片证据。** 要让照片改变状态，规则就得去读照片；证据规则只数账号。
- **通知。** 不发邮件，也不推送，因为这个循环靠的是下次路过，而不是一条提醒。
- **自助注册。** 账号是预置的，这样每一份上报都已经有一个可以动权重的归属人。
- **评论和楼中楼。** 一个状态、一个数量和一个日期，就是下一个读者在桌前需要的东西。
- **徽章和代金券。** 它们只出现在海报上；没有一行代码会发。
- **离线模式和编辑。** 插座的编号由迁移写一次，界面上永远不改。

## 需要种子数据才能看到的几行

有三行靠的不是规则，而是种子数据。队列里有条目，只是因为迁移 V6 把 `MW-T1-0003` 标成松动、把 `CPD-LG01-0007` 标成没电，而 V7 在学习室 4 里留了两个死插座。过期标签只在第一次加载时出现，因为 `KK-101-0004` 被盖上了 45 天前的时间。上报和维修这两行在有人登录之前根本没法演示，而两个演示学生都是从权重 1.0 起步，背后没有任何已结算的上报。
